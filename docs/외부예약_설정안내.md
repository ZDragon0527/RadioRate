# 외부 예약 서비스로 데이터 수집 주기 맞추기 (cron-job.org)

GitHub Actions의 자체 예약(schedule)은 GitHub 서버가 붐빌 때 지연되거나 건너뛰는 일이 잦아서, "30분마다"로 설정해도 실제로는 몇 시간씩 비는 경우가 있습니다.
그래서 외부 예약 서비스가 **약 10분마다** GitHub에 "수집 워크플로를 실행하라"고 요청하도록 설정합니다. 자체 예약은 1시간 간격 예비용으로 남아 있습니다.

소요 시간: 약 10분. 준비물: GitHub 계정(ZDragon0527), 이메일 주소.

---

## 1단계. GitHub 접근 토큰 만들기 (RadioRate 저장소의 Actions 실행 권한만)

1. GitHub 오른쪽 위 프로필 사진 → **Settings**를 엽니다.
2. 왼쪽 맨 아래 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**을 누릅니다.
3. 다음과 같이 입력합니다.
   - **Token name:** `radiorate-cron` (아무 이름이나 가능)
   - **Expiration:** 원하는 기간 (예: 1년). **만료일을 달력에 적어 두세요.** 만료되면 4단계부터 다시 해야 합니다.
   - **Repository access:** **Only select repositories** → `ZDragon0527/RadioRate`만 선택
   - **Permissions → Repository permissions → Actions:** **Read and write**
     - 다른 권한은 건드리지 않습니다. Metadata: Read-only는 자동으로 붙습니다.
4. **Generate token**을 누르고, 화면에 한 번만 보이는 토큰(`github_pat_`로 시작)을 복사해 둡니다.
   - 이 토큰은 비밀번호와 같습니다. 다른 사람에게 보내거나 저장소에 올리지 마세요.
   - 권한이 "RadioRate 저장소의 워크플로 실행"으로만 좁혀져 있어, 유출되더라도 코드나 인증키는 볼 수 없습니다.

## 2단계. cron-job.org 가입

1. https://cron-job.org 에서 **Sign up**으로 무료 가입한 뒤 이메일 인증을 합니다.
2. 로그인 후 **Settings**에서 시간대를 **Asia/Seoul**로 맞추면 실행 기록을 보기 편합니다(선택).

## 3단계. 예약 작업 만들기

**Dashboard → Cronjobs → Create cronjob**

**[Common 탭]**

| 항목 | 입력값 |
|---|---|
| Title | `RadioRate 데이터 수집` |
| URL | `https://api.github.com/repos/ZDragon0527/RadioRate/actions/workflows/update-radiation.yml/dispatches` |
| Execution schedule | **Every 10 minutes** |

**[Advanced 탭]**

| 항목 | 입력값 |
|---|---|
| Request method | **POST** |
| Headers (항목 3개 추가) | `Authorization` : `Bearer 1단계에서_복사한_토큰` |
| | `Accept` : `application/vnd.github+json` |
| | `X-GitHub-Api-Version` : `2022-11-28` |
| Request body | `{"ref":"main"}` |

**[Notifications]** (권장) "Notify me when execution fails"를 켜 두면 토큰이 만료되거나 오류가 날 때 메일이 옵니다.

**Create**(또는 Save)로 저장합니다.

※ 메뉴와 항목 이름은 cron-job.org 화면 개편에 따라 조금 다를 수 있습니다.

## 4단계. 동작 확인

1. 만든 작업의 **Test run**(또는 실행 기록)에서 응답 상태가 **204**이면 성공입니다.
   - **401 / 403:** 토큰이 틀렸거나, Actions 권한이 Read and write가 아니거나, 저장소 선택이 빠졌습니다.
   - **404:** URL 오타입니다. `update-radiation.yml` 철자를 확인하세요.
   - **422:** Request body가 `{"ref":"main"}`이 맞는지 확인하세요.
2. GitHub **Actions** 탭 → "방사선량 데이터 수집 및 배포" 목록에 `workflow_dispatch`로 표시된 실행이 새로 생기면 정상입니다.
3. 약 1~2분 뒤 사이트를 새로고침하면, 상단 배너의 **"마지막 수집"**이 방금 시각으로 바뀝니다.

## 참고

- **API 호출량:** 10분 간격이면 수집이 하루 약 144회이고, 1회당 공공데이터포털 API를 5번 호출합니다. 예비 1시간 간격 24회를 더하면 하루 약 840건으로, 일일 트래픽 한도(10,000건)의 약 8%입니다.
- **멈추고 싶을 때:** cron-job.org에서 작업을 끄면 됩니다. GitHub 예비 예약(1시간 간격)은 계속 동작합니다.
- **토큰 교체:** 1단계에서 새 토큰을 만든 뒤, 3단계 Headers의 `Authorization` 값만 바꾸면 됩니다.
